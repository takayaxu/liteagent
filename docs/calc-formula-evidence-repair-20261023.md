# 年度变化计算：源引用、Calc 求值与回读核验

本次修复第 6 题暴露的“模型在文本中算出错误常量，再把常量写进表格”的执行缺口。
适用范围是已有指令解析器可明确识别的新表年度百分比变化汇总：目标表、输出表头、
源列名及连续年份区间均来自用户指令。没有题号、固定文件名、年份、数值或公式答案。
其他计算类型尚未接入这个计算契约。

## 行为

- 计算列必须由模型提交公式及显式的源表单元格引用；继续使用公开的
  `range.write` typed `kind=formula` 或 `cells.set_formulas`。
- 标题和年份标签仍允许字面量。模型可一次提交混合矩阵，也可先写标签再写公式。
  普通数字或数字文本不能作为派生结果写入计算列；`=0.3169` 这样的常量公式也不满足源引用要求。
- 执行层用读取到的源表头、年份和坐标检查引用对应的列、当前年及前一年。
  目标表头和年份可由候选混合矩阵或之前执行的标签写入识别；不会为模型生成、替换公式或目标。
- 求值复用 Calc Adapter 原有的 `calculateAll()`、公式错误回滚和原生回读。
  脚本不会用自己算出的值替换模型参数。
- 现有 `completion_outcomes` 检查每个输出的原生公式、类型及求值结果，独立核对
  `(current - previous) / previous`，同时要求百分比显示和正常年份显示。
  正确引用但错误运算符、常量公式、错行、错列、数值不符不能作为完成证据。
- 最终变化后必须保存，并回读完整结果及标签。修改源或输出后，旧证据失效。
  完成检查发现缺口时，复用现有恢复工具面保留读取、公式写入、格式和保存能力；
  不需要先提交完成声明，也不增加一轮模型审查。
- 两种公式写入 API 均可完成，不再因为仅用了其中一种而要求重复写入。
  原有独立读审查仍优先：待审读取必须先完成 `read_audit`。

## 限制

本次不是全体 Calc 算术或所有自然语言计算请求的通用解析器。当前只对明确可识别的年度变化
操作实施强约束。源表必须能从原生读取中唯一识别；多个同名结构的候选源、重复年份、截断数据、
零分母会保留未满足状态。公式引用检查支持简单 A1 单元格引用（含绝对地址及带引号表名），
暂不接受命名范围、INDIRECT、外部引用、范围聚合或中间计算链作为这个操作的计算证据。

尚未用本次修改重新运行 OSWorld，因此不能据此宣称第 6 题已通过。
新复跑仍须先提交源码，再从提交创建干净运行工作树。

## 第一次 OS 复跑中发现的协议恢复问题

`a3e8e4c` 的第 6 题复跑中，常量未进入计算列，但模型先把公式作为普通字符串写入，
又混淆源表与目标表的行号。原错误消息把公式文本误称为预计算常量，逐格重复且没有
实际/所需源地址，模型持续将错行反馈误读为缺少工作表前缀。修复为：

- 公式文本错误优先分类，明确 typed formula 的参数形状，并说明整批拒绝未写入任何标签或值。
- 引用错误报告实际及所需源地址；批量错误有界展示，不生成替代公式。
- 模型上下文在压缩后追加原生“年份、列名、当前/上年源地址与值、已存在的目标标签”事实，
  不生成运算表达式或计算答案。
- 计算结果尚未成立时，进度摘要保留 outcome_verification，不能因为写过表头就标成 mutation_complete。

本次还观察到独立读审查将“完整读到计算列为空”误判成观察不充分，并把缺失公式作为
missing_evidence。已明确输入充分性与任务完成的区别：完整读取到的错误/空输出也是
有效观察，可据此恢复写入；充分 verdict 必须有空缺口数组和 continue，schema 与
运行状态校验共同约束。结果错误仍由现有完成检查拒绝，未放宽最终完成条件。

### 流式请求与 episode 总预算

复跑还暴露出网络 read timeout 不能约束整段 SSE 请求：只要连接持续有数据，单轮
生成就可能把 1800 秒总预算拖过。已将运行器的绝对 monotonic 截止时间传给模型客户端，
用有界等待覆盖连接建立和整段流聚合。截止后立即丢弃迟到响应、异步关闭连接；
工作线程只处理模型网络响应，不操作桌面或 RuntimeState。网络读取超时和原重试预算仍保留。
流持续产生 chunk、首响应阻塞、迟到响应和原始异常传播均有测试。

包含这些修复的相关测试共 166 项通过。两个原节点模型重放中，模型分别自主提交了
正确的 15 个源引用公式，以及“空输出为充分观察、继续写入”的审查结论。
重放不执行桌面，不等同 OSWorld 得分；完整复跑结果单独记录。
