# 分类百分比透视表的计数字段与最终内容核验

第 24 题原失败轨迹中，模型主动把 Respondents 当作“任意非空记录列”进行计数。
完整数据恰好没有空分类，所以三个百分比分布数值正确，但输出表头均成为
`Count - Respondents`，而不是各自分类的计数表头。改变计数字段改变了度量语义；
Adapter 没有把正确的分类参数偷偷换成 Respondents。

已有工具说明允许同一源字段同时用于 row_fields 和 COUNT，并已解释度量字段影响
输出表头。本次不是重复增加这句说明：对公共指令明确列出独立分类百分比、且完整
原生源数据能唯一解析字段的情形，增加任务条件 schema，将行字段和 COUNT 度量
绑定到同一实际分类字段，允许 total_percentage 或单值列的等价 column_percentage。
没有任务编号、参考文件或标准答案参与运行时解析。

另外，LibreOffice 为同字段分组和计数创建内部重复维度。getDataPilotFields 排除
重复维度，旧 workbook.inspect 因而可能漏掉正确的 COUNT 数据字段。本次改用
getRowFields/getColumnFields/getPageFields/getDataFields 的索引集合；重复维度的
内部星号后缀只在与实际基础字段唯一匹配时解析，不盲目删除真实表头里的星号。

旧完成门对独立求和有数据验证，但百分比语义解析为空后直接跳过了这一层。本次
增加分类百分比结果契约，完成检查同时要求：

- 完整源范围、每行原生值和单元格类型，源证据不能早于后续源编辑。
- 正确源范围、独立分组、同分类 COUNT、百分比计算方式；一张表对应一个分类。
- 最终编辑和保存之后，覆盖全部输出单元格的原生回读；标题或创建时预览不足以完成。
- 分类和计数表头精确匹配实际源字段；每个源分类恰好出现一次，无遗漏、重复或额外项。
- 每个结果原生数值等于从源数据重算的比例；显示必须为百分比，舍入容差跟随显示精度。
- 总计数值及显示为 100%；要求堆叠时检查表格不重叠，并回读核对分隔空行。

缺项以 missing_observation 或 state_mismatch 进入现有 completion_outcomes 账本，
保留检查、替换原生透视表、格式和保存工具。无需模型先声明“发现偏差”；缺陷持续到
新的完整原生证据消除。审查通过后直接终止，不增加通过后的修复或审计。

实现限于公共文本可明确解析的独立分类频率百分比；不把加权占比、销售额占比、
交叉表或未命名的泛化百分比指令擅自解释成分类 COUNT。这些仍走其他既有检查和
模型审查，并不因此具备通用单元格语义证明能力。本次没有修改 OSWorld evaluator。
