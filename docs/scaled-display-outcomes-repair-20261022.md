# Calc 缩放显示结果核验修复

2026-10-22。第 19 题失败中，模型对空白目标设置单位格式并保存，随后把
`range.set_scaled_display` 成功误认为目标数值已经生成。完成门拒绝了该声明，
但只提示缺少回读和 `range.copy`，没有把目标仍为空报告成具体结果缺陷。

## 根因与修复

格式化 API 保持原子语义：修改数字显示格式，不搬运源值。复制、公式和写值
工具在原失败轨迹中一直可用，问题不在工具被隐藏。

新增 `integrations/lite_agent/calc_scaled_outcomes.py`，读取任务文本中的源列名、
目标列、数量级、精度、单位和间隔，再依据工作簿检查与原生单元格观察核验：

- 从观察到的源表头、工作表和已用范围确定全部源数据行；分段读取可以合并，
  缺行、截断或其他工作簿的观察不能证明结果完整。
- 使用原生值计算目标值，按 half-up 舍入；比较目标实际值及显示文本，覆盖精度、
  单位、空格、漏行、空白值、错误缩放和掩盖错误数值的显示。
- 接受原数值加缩放格式、转换/舍入后的数值加单位格式，以及符合结果要求的
  文本或 TEXT 公式。不强制通过 `range.copy` 或 `range.set_scaled_display` 完成。
- 变更后要求保存并重新读取全部目标范围。只读、保存或成功的无关复制不会
  清除仍然存在的结果缺项。

缺项沿用实际运行链路的 `completion_outcomes` 契约，带有目标、观察值、
期望值、证据步骤及修复工具。每轮根据原始账本重新生成，因此不会随着短上下文
或一次成功读取而丢失。缺项存在时保留复制、公式、写值、格式化、读取和保存
工具；模型自行选择参数和修复方式，框架不代写目标数值。

补充核查纠正了前次分析的一点：`pending_completion_recovery` 虽然有“遇到
成功事件即返回 None”的旧实现，但当前没有运行时调用者。它不是本题循环的
直接原因；本次修复接入实际使用的结果缺陷账本，未修改这个闲置辅助函数。

## 适用范围

新增原生核验针对明确引用带引号源列名，并指定目标列、数量级、单位和小数位的
表示转换请求，支持同一工作表逐行输出。仅从任务指令和原生观察推导，不读取
题号、golden 或 evaluator。尚不能解析的语义沿用原有门禁，不宣称所有自然语言
任务均已具备单元格结果证明。当前支持默认小数点和常见德语/西语/意语/葡语
原生数值格式；其他区域化数字写法需要进一步扩展。
